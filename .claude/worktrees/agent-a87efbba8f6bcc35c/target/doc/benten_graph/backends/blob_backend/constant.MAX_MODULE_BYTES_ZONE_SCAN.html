Constant MAX_MODULE_BYTES_ZONE_SCAN 

pub const MAX_MODULE_BYTES_ZONE_SCAN: usize = 100_000;
Expand description

Hard cap on the number of system:ModuleBytes Nodes a single RedbBlobBackend::get_sync / RedbBlobBackend::list_blob_cids scan will decode before refusing (#567, META #629 DoS-via-unbounded- decode benten-graph slice).

Both methods do an O(N) linear scan that decodes every Node body in the system:ModuleBytes zone. The zone is system-zone (privileged-write only — see MODULE_BYTES_LABEL) so an unprivileged peer cannot inflate it directly, but the O(N)-decode-per-fetch amplification is a real cost ceiling for legitimately-large module sets and a defense-in- depth bound should a privileged-write path ever be reached unexpectedly. 100k modules is far beyond any realistic deployment (modules are operator-curated, not user-generated) while still bounding the worst- case decode work a single scan can perform. Exceeding it surfaces GraphError::DecodeTooLarge rather than silently doing unbounded work.
