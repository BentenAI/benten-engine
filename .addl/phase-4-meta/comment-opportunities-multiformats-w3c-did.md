## 5. Cluster-wide pattern observations

1. **The W3C VC WG's `vc-di-quantum-safe` spec is the operational center of gravity for PQ-Multikey codepoint registration right now.** Wind4Greg drove ~7 issue closures via PR #10/#11 on 2026-05-19; ML-DSA pub/priv + SLH-DSA pub codecs are registered (multicodec PR #399 merged 2026-04-17); SLH-DSA-priv (PR #401) is in flight. **There is currently no codepoint or normative spec text for *hybrid composite* signatures.** This is the largest open gap Benten can productively name with an adopter datapoint. Three leverage points converge here: di-quantum-safe issue #5 (N3) + did-key-spec issue #74 (already drafted) + vc-data-integrity issue #338 (N1).

2. **CID-1.0 (= `w3c/cid`) is THE normative source for Multikey + Multibase rules going forward** — the older `w3c-ccg/multikey` repo doesn't exist as a separate thing; Multikey is a section in cid-1.0. Any Benten engagement that "looks like a multikey comment" should land on `w3c/cid` (very active, 2026-05 issue burst, dlongley engaged).

3. **The "any multikey allowed, did:key extensible without spec amendment" emerging consensus** (silverpill / vdods / peacekeeper in did-key-spec #70 + the lidel/achingbrain framing in multicodec PR #400) is **structurally already won** even without a normative WG resolution; di-quantum-safe's habit of registering codecs via multicodec PRs (#399, #401) is the de facto extension pathway. Benten's already-drafted endorsement of #70 reinforces a settled consensus; reinforcement still has signal value but the urgency is lower than for #74 (PQ in did:key, which is a true open question).

4. **Constant-time secretKeyMultibase decoding (`w3c/cid #162`) is the highest-leverage *technical* PR-shaped comment available right now** — dlongley explicitly asked for concrete proposals 2025-11-09 and the thread has been quiet since. PQ key sizes make this more painful, giving Benten a unique adopter angle.

5. **Spec-WG vs adopter velocity mismatch is real.** Did-key-spec #70 hasn't moved in 14 months; vc-di-quantum-safe shipped ~7 closures in one day (2026-05-19); ucan-wg shipped 4 new issues in May 2026. The clusters with high velocity (di-quantum-safe, w3c/cid, ucan-wg) are where adopter signal lands quickly; the dormant clusters (did-key-spec older issues, varsig 2023 threads, KERI) need a reason-to-revive that an adopter comment can sometimes provide, sometimes not.

6. **A "Composite Multikey" subsection in `w3c-ccg/di-quantum-safe` may be the single highest-leverage cross-cutting proposal** — it would simultaneously address di-quantum-safe #5 (Benten N3 above), give multicodec PR #400's container-codec pattern a PQ-applicable precedent, and answer the implicit question in did-key-spec #74 (how to land PQ in did:key without ratcheting one specific algorithm into spec text). Benten could responsibly *signal interest* in this shape without proposing it ourselves (5-week-old project should not propose normative spec sections).

7. **The `ChainAgnostic/varsig` repo is effectively dormant on the "sign over algorithm choice" question** (#12 closed-by-disagreement 2023; #19, #20 low activity) — varsig adopters are likely doing this work in-implementation; if Benten lands the LAMPS-composite-binding work in our own varsig integration, our experience report would be re-opening signal worth.

8. **Total threads scanned: ~95 across 22 repos.** Breadth covered: multiformats org (6 repos), w3c (cid + vc-data-integrity + vc-di-quantum-safe + vc-jose-cose + webauthn + webcrypto + vc-barcodes + did-extensions + security-guidelines-cryptography), w3c-ccg (did-key-spec + did-method-web + di-quantum-safe + did-resolution + did-cel-spec + community + did-recovery), DIF/decentralized-identity (did-resolver + did-jwt + sidetree + peer-did-method-spec + keri + credential-manifest + cawg-identity-assertion), ChainAgnostic/varsig, ucan-wg (spec + delegation + invocation + revocation + rs-ucan), spruceid/ssi.
